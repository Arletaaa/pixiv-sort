# pixiv 收藏排序

一个 Tampermonkey 用户脚本。在 pixiv 的标签搜索页，把结果按 **收藏数** 或 **点击量** 重新排序，省去一页页翻，找一个题材里最受欢迎的作品。

不是官方产品，与 pixiv 无关联。

## 安装

### 方式一：网址安装（推荐，可自动更新）

浏览器装好 [Tampermonkey](https://www.tampermonkey.net/) 后，打开下面这个地址，会弹出安装页，点「安装」：

```
https://cdn.jsdelivr.net/gh/Arletaaa/pixiv-sort@main/pixiv-sort.user.js
```

这个地址同时也是 Tampermonkey 的更新源，填在 About → Website 里即可。

### 方式二：本地文件

把 `pixiv-sort.user.js` 拖进 Chrome 窗口，或打开 Tampermonkey 面板 → 实用工具 → 从文件导入。

### 权限说明

安装页会申请两项权限，都是下载原图必需的，脚本不会用于其它用途：

- `GM_xmlhttpRequest` / `GM_download`：跨域取图、保存文件
- `i.pximg.net`：原图域名

## 使用

1. 打开任意标签搜索页，例如 `https://www.pixiv.net/tags/初音ミク/artworks`
2. 点右下角的「**收藏排序**」浮标
3. 点「**开始抓取**」
4. 结果按当前排序依据从高到低排列，鼠标悬停缩略图出现「⬇ 原图」

### 控制条

| 项目 | 说明 |
| --- | --- |
| 基础间隔 | 每次请求前的等待时间。实际值在此值的 **0.6–1.4 倍**之间随机，右侧实时显示区间 |
| 抓取范围 | 从第 X 页到第 Y 页，合并后统一排序；1 页约 60 条 |
| 每页显示 | 面板内每页展示 12 / 24 / 48 条 |
| 屏蔽 R-18 | 服务端参数 `mode=safe` |
| 屏蔽 AI 作品 | 服务端参数 `ai_type=1` |

### 设置

| 项目 | 说明 |
| --- | --- |
| 排序依据 | 收藏数 / 点击量。切换即时重排，不重新请求 |
| 只显示达到阈值 | 收藏数或点击量 ≥ N 才显示。改动即时生效 |
| 保存位置 | Chrome 下载目录，或授权任意本地文件夹 |
| 子目录 | 仅「Chrome 下载目录」模式生效，如 `pixiv/2024` |
| 文件名 | 默认 `{title}_{id}`，可用占位 `{title}` `{id}` `{page}` |
| 本地缓存 | 只存作品 ID 与数值，7 天过期，可一键清除 |

## 常见问题

**排序没生效，角标全是 0？**
搜索接口有时不返回收藏数/点击量。点状态栏右侧的「**补全数据**」，脚本会逐条请求作品详情补上（一次同时拿到两个数值），结果缓存 7 天。

**面板里的缩略图是空白方块？**
正常占位。图挂了会保留正方形占位而不是塌成一条线；滚动到可见区域会自动加载。

**为什么抓取很慢？**
受「基础间隔」和「抓取范围」共同决定。1 页 60 条约 2–5 秒；补全数据是逐条请求，最慢。想快就调小间隔，但要承担限流风险。

**提示「第 X 页被限流」怎么办？**
脚本会自动退避重试 3 次。仍失败就把间隔翻倍再试。随机间隔只能让请求看起来不像脚本，**总量才是真正决定安全的东西**。

**「指定文件夹」模式为什么每次重启要再授权？**
这是 File System Access 的安全设计：浏览器不给网页脚本永久写权限。点一次「重新授权」即可。浏览器也不会把完整路径告诉脚本，所以设置里只显示文件夹名。

**下载没有进度条？**
指定文件夹模式不走浏览器下载管理。面板状态栏会显示「已下载 5/7」这样的计数，点一下清零。

**多页作品怎么下全部？**
点「⬇ 原图」后会列出 p0…pN，点一下下一页。脚本不提供一键全下。

## 已知限制

- 收藏数 / 点击量字段依赖 pixiv 内部接口，接口调整可能导致排序失效（有「补全数据」兜底）
- 只匹配 `https://www.pixiv.net/*`，只在 `/tags/关键词` 页面显示按钮
- 站点是 SPA，切换关键词后面板会自动重置数据，需要重新抓取
- 不提供批量下载、不绕过 Premium、不做自动登录
